Du RAG avancé au RAG agentique multi-agents

Un assistant qui répond aux questions sur le RGPD en s'appuyant uniquement sur le texte du règlement. On compare un pipeline RAG classique et un graphe de 7 agents LangGraph (planification, correction CRAG, réflexion), avec le même LLM local et le même juge RAGAS.

99 articles du RGPD LangGraph Ollama · 100 % local ChromaDB + BM25 RAGAS

Le graphe des agents

Chaque nœud est un agent avec un rôle, un prompt et une sortie structurée. Les flèches en pointillés sont les boucles : reformulation (CRAG) et révision (Reflexion), bornées pour garantir la terminaison. Cliquez sur un agent pour voir son rôle, ou rejouez le parcours réel d'une question.

Tableau des résultats

Méthode

Protocole équitable

  1. Même corpus, même index : RGPD (UE 2016/679), 99 articles, chunks de 300 caractères dans ChromaDB, embeddings paraphrase-multilingual-MiniLM-L12-v2.
  2. Même LLM pour les deux systèmes : qwen2.5:7b via Ollama, en local.
  3. Même premier jet : le rédacteur agentique utilise le même prompt RGPD que la baseline ; l'écart vient de l'orchestration.
  4. Même juge : qwen2.5:14b, température 0, plus gros que le modèle évalué.
  5. Quatre métriques RAGAS : faithfulness, answer relevancy, context precision, context recall.

Limites

  • 10 + 10 questions : les écarts sur une question isolée sont bruités ; on lit les moyennes et les tendances.
  • Le juge est un LLM local de 14 milliards de paramètres : moins fiable qu'un grand modèle commercial, mais identique pour les deux systèmes.
  • Les outils de l'agent de recherche (BM25 hybride, reranker multilingue) améliorent aussi la recherche en eux-mêmes ; ils font partie de sa boîte à outils.
  • Le RAG agentique est plus lent (6 à 9 appels au LLM par question contre 2).
